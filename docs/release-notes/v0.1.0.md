# v0.1.0

First public release of `@accelerationagency/cesium-i3s-extensions`: runtime patches for CesiumJS 1.145's I3S support (`cesium` 1.145.0 / `@cesium/engine` 26.3.0, pinned exactly), plus a build-time worker patch you generate against your own installed Cesium.

## Added

- **[Web Mercator I3S scene layers](https://github.com/AccelerationAgency/cesium-i3s-extensions/blob/v0.1.0/docs/01-web-mercator-i3s.md)** — load a `wkid` 102100/3857/102113/900913 scene layer that stock CesiumJS 1.145 refuses outright with `Unsupported spatial reference`, without republishing the service in WGS84.
- **[Atlas UV remap](https://github.com/AccelerationAgency/cesium-i3s-extensions/blob/v0.1.0/docs/02-atlas-uv.md)** — per-pixel remap of tiling atlas facade UVs into their region, replacing the stock per-vertex crop, for layers whose per-face UVs run outside `[0,1]`.
- **[Gradient-correct mip selection](https://github.com/AccelerationAgency/cesium-i3s-extensions/blob/v0.1.0/docs/03-mip-shimmer.md)** — `textureGrad` with derivatives rescaled into atlas space, avoiding both tile-boundary seams and moiré on minified surfaces.
- **[Layer loading and cache tuning](https://github.com/AccelerationAgency/cesium-i3s-extensions/blob/v0.1.0/docs/04-layer-loading-and-cache.md)** — measured `Cesium3DTileset` defaults for I3S buildings, and a visibility-driven loader that fetches a layer only once it's actually shown.
- `cesium-i3s-build-worker` / `cesium-i3s-verify-worker` CLIs to build and verify the patched decode worker against your own installed `@cesium/engine`.
- A local demo (`npm run demo`) comparing stock CesiumJS against this package on three public ArcGIS Online scene layers.

## Fixed

- `uv-region` now survives the vertex de-indexing `generateNormals` can trigger, keeping atlas regions in sync with their vertices.
- Extent reprojection now runs at layer construction, matching when `I3SDataProvider.fromUrl` actually reads a layer's extent.
- The atlas shader is guarded so an untextured primitive sharing an atlas layer no longer breaks shader compilation for the whole scene.
- A synchronously-throwing `load()` is normalised into the same rejection path as a rejected promise.

## Known issues

- Building Scene Layer extents aren't reprojected (a separate provider code path, not covered by this fix).
- The Boston demo layer's normal-map and metallic-roughness textures don't load under stock CesiumJS 1.145 (or 1.138) at all — unrelated to this package.
- `cesium@1.145.0` consumers should add a `@cesium/widgets: 16.2.0` override/resolution in their own project, so a future widgets release built on a newer engine can't cause a duplicate `@cesium/engine` install — see the README's Compatibility section.
